# PLAN (대회 당일 10:00~13:00 기획 회의에서 채운다)

A 는 "무엇을, 누구를 위해" (기획), B 는 "어떻게, 누가" (구현) 다. 에이전트는 기능을 만들 때 B 의 자기 기능 체크리스트를 따르고, 방향이 헷갈리면 A 를 본다.
정민은 회의 메모를 Claude Code 의 `/plan` 스킬에 넣어 A·B 초안과 계약 초안을 만든다.

|---|---|---|

### 아이디어 평가표 (11:00 수렴 때 사용)
우리 팀이 중요하게 보는 두 축은 **서비스 기획력**과 **결과물 완성도**다. 클라우드·AI 는 그 둘을 받쳐 주는 수단으로 본다.
| 기준 | 가중치 | 1점 | 3점 |
|---|---|---|---|
| 문제의 구체성 | ×3 | "많은 사람이 불편하다" | "누가, 언제, 어떤 상황에서, 무엇 때문에" 를 한 문장으로 말할 수 있다 |
| 핵심 사용자 | ×2 | 사용자가 여럿이거나 모호 | 핵심 사용자 한 명(페르소나)이 정해진다 |
| 데모로 보여 주기 | ×3 | 설명해야 효과를 안다 | 3분 시연 안에 "전 → 후" 가 화면으로 보인다 |
| 28시간 완성 가능성 | ×3 | 구현 등급 "위험" 이 2개 이상 | 전부 "안전", 또는 "위험" 1개에 대안이 있다 |
| 데이터 확보 | ×2 | 당일 구할 수 있을지 모름 | 지금 받을 수 있는 공개 데이터나 직접 만들 수 있는 데이터가 있다 |
| 클라우드·AI 의 필요성 | ×1 | 없어도 된다 | 빠지면 서비스가 성립하지 않는다 |

구현 등급 (자세한 표와 대안은 `/plan` 스킬):
- **안전**: 화면 + API + DB 저장·조회, LLM 한 번 호출(요약·분류·추출·JSON 생성), 차트 대시보드, 표·검색·필터·폼
- **위험** (+2~4시간, 하나만): 벡터 검색 RAG, 파일 업로드 파싱, 지도, 응답 스트리밍, 외부 API 키 발급, 대량 데이터 적재
- **피함**: 로그인·회원가입, 실시간 동기화, 결제, 모바일 앱, 모델 학습, 대규모 크롤링
