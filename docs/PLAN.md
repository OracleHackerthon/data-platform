## A. 제품 (무엇을, 누구를 위해)
- 주제: 제조 데이터 검증·거래 플랫폼 (서비스명 `(정할 것)`)
- 해결할 문제: 직원 50~299명 제조 공장의 품질팀장은 AI 검사를 도입하려 할 때, 공정 데이터를 외부에 줄 수 없어서 어느 AI 업체가 자기 공정을 잘 푸는지 판단하지 못한다.
- 핵심 사용자: 공장 품질팀장 (보조 사용자: 제조 AI 스타트업 담당자)
- 지금은 어떻게 하고 있나: 컨설팅(단계당 수천만 원), 매칭 플랫폼(영상 업로드 필요, 실제 성능 비교 없음), 데이터 거래소(샘플 공개 필요). 결국 레퍼런스가 있는 기존 업체에 맡기거나 포기한다.
- 우리 서비스 한 줄: 공장 데이터를 내보내지 않고 AI 업체의 실력을 내 데이터로 비교하고, 고른 업체와만 안전하게 거래한다.
- 사용자 흐름: 1. 진단·공개 정책 설정 → 2. 익명 과제 공개 → 3. 스타트업 제출·DB 안 채점 → 4. 익명 순위표에서 선택 → 5. 실명 공개·계약
- 완성도 기준: 역할 전환(공장 ↔ 스타트업) 후 상대 화면에 상태 변화가 바로 보이고, 순위표 → 실명 공개 흐름이 끊기지 않는다.

### 데모 시나리오 (3분, 이 순서가 MVP 범위다)
| # | 역할 | 사용자가 하는 일 | 화면에 보이는 것 | 실제 동작 / 미리 준비 |
|---|---|---|---|---|
| 1 | 공장 | 내 데이터셋 "진단하기" | 품질 점수, 지표 5개, AI 진단 리포트, 과제 카드 | **실제**: SQL 품질 지표, LLM 리포트 / 준비: 데이터셋 적재 |
| 2 | 공장 | 공개 정책 설정(합성 수준 "중간", 경쟁 업종 차단) → "과제 공개" | 과제 상태 "공개됨" | **실제**: 정책·상태 저장 |
| 3 | 스타트업 | 역할 전환 → 카탈로그에서 과제 열기 | 익명 과제 카드, 합성 데이터 미리보기, "원본은 보이지 않음" 표시 | **실제**: 공개·차단 정책 반영 조회 / 준비: 합성 데이터(중간 수준) |
| 4 | 스타트업 | "모델 제출" → 평가 실행 | 진행 표시 → 내 점수 (정확도, 불량 검출률, 오탐률) | **실제**: 숨긴 라벨과 비교하는 SQL 채점 / 준비: 업체별 예측값 |
| 5 | 공장 | 역할 전환 → 익명 순위표 → 업체 B "연락 요청" | 업체 A/B/C 점수와 검증 배지, 요청 완료 | **실제**: 요청 저장 / 준비: 업체 A·C 제출과 배지 |
| 6 | 스타트업 | 요청 "수락" | 양쪽 실명·연락처 공개 | **실제**: 상태 변경 |
| 7 | 공장 | 계약 선택지(목적·기간·범위·전달 방식) 저장 | 거래 단계: 계약 → 입금 대기 → 접근 허용 → 정산 | **실제**: 계약 저장 / 결제는 단계 표시만 (MOCK) |
| 8 | 공장 | 접근 기록 보기 | 1~7 동안의 기록. "원본 다운로드 0건" | **실제**: 기록 조회 |

### 발표에서 솔직하게 말할 것
- 업체 모델의 **예측값은 미리 만들어 둔 것**이고, **채점은 실제로 DB 안에서** 한다. 실서비스에서는 이 자리에 격리된 실행 환경이 들어간다.
- 합성 데이터는 미리 생성했다. 진단 SQL·채점 SQL 은 데이터셋 ID 기준이라 데이터만 바꾸면 그대로 동작한다 (하드코딩 금지 이유).

### B-1. 데이터 진단 + 공개 정책 (화면: 예원 / API: 영진 / AI: 승연, 예상 4.5h)
- 시나리오 단계: 1, 2
- 화면 구성: 대시보드. 위에 품질 점수 Card + 지표 5개 Card, 가운데 AI 진단 리포트·과제 카드(Card), 아래 공개 정책 Field(Select: 합성 수준, 경쟁 업종 차단) + "과제 공개" Button. 로딩은 Skeleton, 결과 알림은 Sonner
- API: `POST /api/datasets/[id]/diagnose`, `PUT /api/tasks/[id]/policy` (`docs/API_CONTRACT.md`)
- AI: `ai/prompts/diagnose.md`, 입력 품질 지표 JSON + 컬럼 목록 → 출력 `{ report, taskCard: { title, problem, metric, dataNeeded } }`
- DB: `DATASETS`, `RAW_ROWS`, `TASKS`
- 완료 조건:
  - [ ] 품질 지표(결측률, 행 수, 수집 기간, 불량 비율, 이상값 비율)가 SQL 로 계산되어 표시된다
  - [ ] 진단 리포트와 과제 카드가 LLM 응답으로 채워진다 (VM 배포본에서 확인, D15)
  - [ ] 정책 저장 후 과제 상태가 "공개됨" 으로 바뀐다

### B-2. 익명 카탈로그 + 합성 데이터 (화면: 예원 / API: 영진 / 데이터: 승연, 예상 3h)

- DB: `TASKS`, `SYNTH_ROWS`, `VENDORS`
- 완료 조건:
  - [ ] 공개된 과제만 보이고, 경쟁 업종 업체로 전환하면 목록이 비어 보인다 (Empty)
  - [ ] 합성 데이터 미리보기와 분포 비교가 보인다. 원본 행은 어떤 응답에도 없다

### B-3. 제출·채점 + 익명 순위표 (화면: 예원 / API: 영진 / 데이터: 승연, 예상 4.5h)
- 시나리오 단계: 4, 5
- 화면 구성: 스타트업 쪽은 과제 상세의 "모델 제출" Button → Spinner → 내 점수 Card. 공장 쪽은 순위표 Table(별칭, 지표 3개, 검증 배지 Badge) + 행마다 "연락 요청" Button
