## A. 제품 (무엇을, 누구를 위해)
- 주제: 제조 데이터 검증·거래 플랫폼 (서비스명 `(정할 것)`)
- 해결할 문제: 직원 50~299명 제조 공장의 품질팀장은 AI 검사를 도입하려 할 때, 공정 데이터를 외부에 줄 수 없어서 어느 AI 업체가 자기 공정을 잘 푸는지 판단하지 못한다.
- 핵심 사용자: 공장 품질팀장 (보조 사용자: 제조 AI 스타트업 담당자)
- 지금은 어떻게 하고 있나: 컨설팅(단계당 수천만 원), 매칭 플랫폼(영상 업로드 필요, 실제 성능 비교 없음), 데이터 거래소(샘플 공개 필요). 결국 레퍼런스가 있는 기존 업체에 맡기거나 포기한다.
- 우리 서비스 한 줄: 공장 데이터를 내보내지 않고 AI 업체의 실력을 내 데이터로 비교하고, 고른 업체와만 안전하게 거래한다.
- 사용자 흐름: 1. 진단·공개 정책 설정 → 2. 익명 과제 공개 → 3. 스타트업 제출·DB 안 채점 → 4. 익명 순위표에서 선택 → 5. 실명 공개·계약
- 완성도 기준: 역할 전환(공장 ↔ 스타트업) 후 상대 화면에 상태 변화가 바로 보이고, 순위표 → 실명 공개 흐름이 끊기지 않는다.

### 발표에서 솔직하게 말할 것
- 업체 모델의 **예측값은 미리 만들어 둔 것**이고, **채점은 실제로 DB 안에서** 한다. 실서비스에서는 이 자리에 격리된 실행 환경이 들어간다.
- 합성 데이터는 미리 생성했다. 진단 SQL·채점 SQL 은 데이터셋 ID 기준이라 데이터만 바꾸면 그대로 동작한다 (하드코딩 금지 이유).
- 가치평가지수는 데이터상품 가치평가 논문의 4개 영역·12개 요소·가중치(AHP)를 가져왔다. 다만 두 가지가 논문과 다르다:
  - 지표 값을 10점으로 바꾸는 구간은 우리가 정했다 (논문 본문에 다 나와 있지 않다).
  - 판매 이력·라이선스처럼 공장 데이터에 없는 지표는 빼고 남은 가중치를 100으로 다시 맞췄다.
  - 지표 두 개는 근사했다: 의미컬럼수는 개수 대신 비율, 정합성율의 오류 건수는 결측 셀 수.
  - 그래서 "논문 모델을 공장 데이터에 맞게 적용" 이라고 말한다. "논문과 같은 점수" 라고 하지 않는다.
- 권장 가격 범위는 지수를 보조 지표로 쓴 것이다. 지수를 금액으로 바로 바꾸지 않고, 최종 가격은 공장이 정한다 (논문의 제안과 같다).

## B. 구현 (어떻게, 누가)
- 데이터셋: UCI **SECOM** (반도체 공정 센서, 1,567행, 익명 센서 컬럼 590개, 불량 104건 약 6.6%, 결측 많음, 타임스탬프 있음) (10/16 AI4I 2020 에서 변경)
  - 바꾼 이유: AI4I 는 결측이 없고 컬럼 이름에 단위가 붙어 있어 가치평가지수가 거의 만점이 된다. 그러면 개선 제안 장면이 밋밋해진다. SECOM 은 결측이 많고 컬럼 이름이 익명이라, 지수가 낮은 요소와 개선 제안이 실제로 나온다.
  - 센서 컬럼은 승연이 추려서 적재한다. **결측이 많은 컬럼을 일부 일부러 포함**해 "의미 컬럼 수"·"정합성" 이 낮게 나오게 한다 → **40개로 적재 완료** (10/16, 상수 컬럼 116개 제외 후 결측 30% 미만에서 불량 상관 상위 32개 + 결측 30% 이상에서 8개. 결측 없는 행은 의미 컬럼 기준 1,525행)
  - 라벨은 원본의 `-1`(정상)/`1`(불량)을 `0`/`1` 로 바꿔 적재한다 (채점 SQL 이 0/1 기준).
- 가치평가지수 (논문 모델 적용, 4개 영역·12개 요소, 가중치 합 100)

모든 기능이 같이 쓰는 뼈대다. 기능 절(B-1~B-6)보다 먼저 만든다.

**화면 경로** (화면 파일은 모두 예원)
| 경로 | 역할 | 시나리오 | 기능 | 부르는 API |
|---|---|---|---|---|
| `/dashboard` | 공장 | 1, 2 | B-1 | `GET /api/tasks/1?role=factory`, diagnose, policy |
| `/catalog` | 스타트업 | 3 | B-2 | `GET /api/tasks` |
| `/tasks/[id]` | 스타트업 | 3, 4 | B-2, B-3 | `GET /api/tasks/[id]`, submissions |

- `/` 는 `/dashboard` 로 이동한다 (10/16 샘플 제거 때 정민이 바꿈, `web/app/page.tsx`).
- 데모 초기화(B-6)는 `curl -X POST <주소>/api/demo/reset` 로 한다. `/admin` 화면은 있으면 좋음.
- 과제 ID 는 경로에서 받는다. 공장 대시보드만 시드 과제 `1` 을 쓴다 (과제가 하나뿐인 범위, A 의 버림 항목).

**역할 상태** (`web/components/role/`, 예원)
- `RoleProvider`: `role`(`factory`/`startup`), `vendorId` 를 Context 로 들고, localStorage 에 저장해 새로고침해도 유지한다. 기본값 `factory`.
- `RoleToggle`: `layout.tsx` 상단에 둔다. 스타트업이면 업체 Select(업체 A~D, 시드 ID `1~4` 상수, 주석으로 `API_CONTRACT` 공통 규칙을 가리킨다)가 보인다.
  - 역할을 바꾸면 그 역할의 첫 화면으로 이동한다 (공장 `/dashboard`, 스타트업 `/catalog`). 상단 메뉴도 역할별로 바뀐다 (공장: 대시보드·순위표·거래·접근 기록 / 스타트업: 카탈로그·거래).
- `useRole()`: `{ role, vendorId, setRole, setVendorId, query }`. `query` 는 `"role=startup&vendorId=2"` 같은 문자열이다.
- 화면은 **클라이언트 컴포넌트에서** `/api/*` 를 부르고, `role`·`vendorId` 가 바뀌면 다시 불러온다 (역할이 localStorage 에 있어 서버 컴포넌트는 알 수 없다).

**API 공통 도우미** (`web/app/api/_lib/`, 영진. `_` 로 시작해 경로가 되지 않는다)
- `getActor(req, body?)`: 쿼리나 본문에서 `role`·`vendorId` 를 읽어 `{ role, vendorId, label }` 을 돌려준다. `label` 은 `"공장"` 또는 `VENDORS.alias`. 값이 틀리면 400 이다.
- `requireRole(actor, "factory")`: 역할이 다르면 403 이다.
- `logAccess(actor, action, target)`: `ACCESS_LOG` 에 INSERT 한다. 실패해도 본 응답은 막지 않고 `console.error` 만 남긴다.
- route 파일은 기존 `db-check` 처럼 `await connection()` 을 두고 try/catch 로 감싸 `ok`/`fail`(`@/lib/api`)로 응답한다. 동적 경로의 `params` 는 `await` 한다 (D10).
- `query` 는 문장마다 따로 커밋한다 (트랜잭션 없음). 그래서:
  - 채점은 `INSERT INTO submissions … SELECT <채점 집계>` **한 문장**으로 쓰고, 저장된 행을 다시 SELECT 해 응답한다.
  - 초기화는 문장 여러 개를 쓴다. 중간에 실패하면 다시 실행하면 되도록 순서와 상관없이 같은 결과가 나오게 쓴다.
- MOCK(D4): 같은 route 파일에서 계약 형태 그대로 고정값을 돌려주고 `// MOCK` 주석을 단다. 실제 구현으로 바꿀 때 화면은 그대로다.

**공유 타입** (`web/lib/types.ts`, 정민)
- 계약의 응답 형태를 TypeScript 타입으로 옮긴 파일이다: `Role`, `Metrics`, `ValueIndex`, `PriceGuide`, `TaskCard`, `TaskDetail`, `TaskSummary`, `Submission`, `LeaderboardRow`, `Deal`, `DealStatus`, `DealStage`, `AccessLog`. 화면(`fetch` 결과)과 API(`ok<T>`)가 같은 타입을 쓴다.
- `API_CONTRACT.md` 가 원본이다. 계약이 바뀌면 같은 PR 에서 이 파일도 고친다.

**AI** (`ai/`, 승연)
- `ai/main.py` 에 `POST /diagnose` 를 둔다 (`DiagnoseIn`: `metrics`, `meta`, `columns`). 순서:
  1. `ask(load_prompt("diagnose"), json.dumps(입력))` **한 번**으로 LLM 판정 3개, 리포트, 과제 카드, 요소별 개선 제안 문장을 받는다.
  2. SQL 지표 + 메타데이터 + LLM 판정을 10점 척도로 바꾸고, 가중치를 곱해 지수를 계산한다. 이 계산은 LLM 이 아니라 파이썬이 한다 (`ai/value_index.py`, 가중치·환산 구간 상수 포함).
  3. `expectedGain` 이 큰 요소부터 개선 제안을 3개 고른다 (같으면 점수가 낮은 요소 먼저). `expectedGain` 은 그 요소가 10점이 될 때 오르는 지수다 (파이썬 계산). 점수만 보면 가중치가 큰 물리적 품질이 빠져 "결측 센서를 다시 모으면 오른다" 장면이 약해진다 (10/16 변경).
- 프롬프트는 "JSON 만 출력" 으로 고정한다. 응답 앞뒤의 코드 블록 표시를 떼고 `json.loads` 한다. 필드가 빠지면 `{ ok: false }` 를 돌려준다 (web 은 502 로 바꾼다).
- web 쪽은 `callAi("/diagnose", …)` 를 기본 제한 시간 60초로 부른다. 화면은 그동안 Skeleton 을 보여 준다.

### B-3. 제출·채점 + 익명 순위표 (화면: 예원 / API: 영진 / 데이터: 승연, 예상 4.5h)
