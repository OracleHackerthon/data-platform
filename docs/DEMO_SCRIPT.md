# DEMO_SCRIPT (담당: 예원 / 금요일 밤부터 채운다)

## 발표 흐름 (목표 시간 합계: 분)
1. 문제 — 누가, 무엇 때문에 불편한가 ( 분)
2. 해결 — 한 문장 요약 ( 분)
3. 데모 — 아래 시연 순서 ( 분)
4. 기술 — 구조도, AI 활용, OCI 활용 ( 분)
5. 마무리 — 기대 효과 ( 분)

## 시연 순서 (3분, 10/17 정민 초안. 발표 대본 16번과 17번 사이)
- 시연 URL: `http://132.145.95.96` (주소창에 `http://` 를 직접 쓴다)
- 시작 전 (매번): `curl -X POST http://132.145.95.96/api/demo/reset` 로 초기화 → 창 두 개를 나란히 띄운다
  - **왼쪽 창**: 첫 화면에서 "공장으로 시작" / **오른쪽 창**: "스타트업으로 시작" (오른쪽 위 업체는 **업체 B** 그대로)
  - 브라우저 두 개(예: Chrome + Edge)로 띄워도 되고, 같은 브라우저 창 두 개도 된다. 역할은 창마다 따로 유지된다
- 상대 창에서 한 일은 **그 창을 한 번 클릭하면** 최신으로 바뀐다 (새로고침 불필요). 아래 "클릭" 표시가 그 시점

| 순서 | 창 | 화면 | 클릭/입력 | 보여줄 결과와 말할 것 | 시간 |
|---|---|---|---|---|---|
| 1 | 공장 | 대시보드 | "진단하기" | 가치평가지수, 4개 영역 레이더, 개선 제안. "원본은 DB 밖으로 나가지 않고, 진단 결과와 무엇을 더 모으면 점수가 오르는지만 봅니다" | 35초 |
| 2 | 공장 | 대시보드 → 과제 등록 | "과제 등록하기" → 합성 데이터 수준 중간, **차단 업종 "반도체 제조" 선택** (기본값은 차단 안 함) → "과제 등록 및 공개" | "공개됨". "스타트업에게는 업체명을 가린 과제와 합성 데이터만 공개됩니다" | 20초 |
| 3 | 스타트업 | 카탈로그 → 과제 상세 | (창 클릭) 과제 카드 → "과제와 합성 데이터 보기" | 익명 과제 카드, 합성 데이터 미리보기, 원본 대비 분포. "원본은 보지 못하고 합성 데이터로 개발합니다" | 25초 |
| 4 | 스타트업 | 과제 상세 | "모델 제출" | 정확도·불량 검출률·오탐률. "채점은 공장 실제 데이터의 숨긴 라벨로 DB 안에서 합니다" | 25초 |
| 5 | 공장 | 순위표 | (창 클릭) 상단 "순위표" → 업체 B "연락 요청" | 업체명을 가린 A/B/C 점수. "공장은 이름이 아니라 점수로 고릅니다" | 20초 |
| 6 | 스타트업 | 거래 → 거래 상세 | (창 클릭) 상단 "거래" → "요청 확인하고 수락하기" → "연락 요청 수락" | 양쪽 실명·연락처 공개. "수락한 순간에만 서로의 이름이 공개됩니다" | 20초 |
| 7 | 공장 | 거래 상세 | (창 클릭) 상단 "거래" → "계약 작성하기" → 가격·목적·기간·범위 선택 → "계약 저장" | 권장 가격 범위(가치평가지수 기반), 거래 단계(계약 → 입금 대기 → 접근 허용 → 정산). "우승자는 데이터 이용권을 사고, 데이터는 격리 환경 안에서만 씁니다" | 25초 |
| 8 | 공장 | 접근 기록 | 상단 "접근 기록" | 1~7의 행동 기록, "원본 다운로드 0건". "누가 무엇을 봤는지 모두 남고, 원본은 한 번도 나가지 않았습니다" | 10초 |

- 시간이 남으면 (선택, 2번 뒤): 스타트업 창 오른쪽 위에서 **업체 D (반도체 제조)** 로 바꾸면 카탈로그가 빈다 → "경쟁 업종은 과제를 볼 수조차 없습니다" → 다시 **업체 B** 로 되돌린다. 리허설에서 빈 화면이 나오는지 먼저 확인할 것
- 시연용 입력값 (7번): 목적 `PoC 검증`, 기간 `3개월`, 범위 `원본 일부(격리 환경)`, 가격은 권장 범위 안의 값

### 발표 대본과 맞출 것 (10/17 점검)
- 1번·20번 슬라이드의 "서비스 이름 미정" → **SynLink**
- 13번 "점수 반올림·제출 횟수 제한·최종 순위는 따로 둔 데이터" 는 **설계**다. 데모 채점은 원본 전체로 하고 횟수 제한이 없다 (`web/app/api/_lib/submissions.ts`). 슬라이드에 "설계" 표시를 하거나 4번 단계에서 "지금은 DB 안 SQL 채점만 시연합니다" 라고 말한다
- 11~14번 (OCI Vault 고객 관리 키, 기밀 컴퓨팅, 네트워크 차단 컨테이너, 모델 암호화) 은 데모에 없다. 기술 슬라이드에서 "데모 구현" 과 "실서비스 설계" 를 나눠 보여 준다. 데모에서 보이는 근거는 원본이 DB 안에만 있고 채점도 DB 안에서 한다는 것, 접근 기록의 "원본 다운로드 0건"
- 16번 수익 세 가지 중 데모에 보이는 것은 "우승자 데이터 이용권" (7번의 권장 가격·계약·거래 단계) 뿐이다. 나머지 둘은 말로 설명한다
