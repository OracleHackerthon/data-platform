# plan: 회의 메모 → PLAN·계약 초안

목표는 13:00 기획 마감을 지키는 것이다. 회의에서 정한 것을 문서로 고정하고, **28시간 안에 완성 가능한 범위로 자르는 것**까지 돕는다.
우리 팀의 우선순위는 **서비스 기획력**과 **결과물 완성도**다. 클라우드·AI 는 이를 받쳐 주는 수단이다.

## 0. 입력
- 사용자가 붙여 넣은 회의 메모 (또는 파일 경로). 없으면 요청한다.
- 먼저 읽을 것: `docs/PLAN.md`(양식과 평가표), `docs/API_CONTRACT.md`(형식, 상태 흐름), `docs/DECISIONS.md`(D1 DB, D4 MOCK 위치, D10 스택), `AGENTS.md` 소유권 표.

## 1. A. 제품 채우기
- 메모에서 문제, 핵심 사용자, 현재 방식, 서비스 한 줄, 사용자 흐름(3~5단계), 데모 시나리오, 완성도 기준, 디자인 방향을 뽑아 채운다.
- **메모에 없는 것은 지어내지 않는다.** 빈칸으로 두고 "회의에서 정할 것" 목록에 올린다.
- 문제 문장이 "많은 사람이 불편하다" 수준이면 "누가 / 언제 / 무엇 때문에" 가 빠졌다고 지적한다 (기획력 평가의 핵심).
- 평가표로 점수를 매겨 보고, 2점 이하인 기준을 알린다.

## 2. MVP 범위 자르기
각 기능을 아래 표로 등급을 매긴다. **"위험" 은 전체에서 하나만** 허용하고, 대안을 함께 적는다. "피함" 은 대체안으로 바꾼다.

| 등급 | 기능 | 비고·대안 |
|---|---|---|
| 안전 | 화면 + API + DB 저장·조회 | 스타터 경로 검증됨 |
| 안전 | LLM 한 번 호출 (요약·분류·추출·추천·JSON 생성) | `ai/llm.py` 의 `ask`. 출력은 JSON 으로 고정 |
| 안전 | 차트 대시보드, 핵심 숫자 카드 | `components/ui/chart`(recharts) |
| 안전 | 표·검색·필터·폼 | Table, Select, Field |
| 위험 | 벡터 검색 RAG (ADB 23ai) | 미검증. 대안: 관련 행을 SQL 로 골라 프롬프트에 넣기 |
| 위험 | 파일 업로드 파싱 (CSV, PDF) | 대안: 데모용 파일을 미리 DB 에 넣어 두고 "선택" 으로 대체 |
| 위험 | 지도 시각화 | 패키지 추가 필요. 대안: 지역별 표·막대 차트 |

| 위험 | 대량 데이터 적재 | 대안: 데모에 필요한 일부만 `INSERT` 스크립트나 Database Actions 의 데이터 불러오기로 |

| 피함 | 모바일 앱 | 반응형 웹 |

## 3. B. 구현 쪼개기와 시간 검사
- 필수 기능마다 PLAN 의 B 양식으로 "화면 / API / AI / DB" 칸을 채우고 칸마다 담당(AGENTS.md 소유권)과 시간을 적는다.
- 시간 기준 (바이브 코딩, 한 칸): 단순 화면 1.5h, 차트 화면 2h, API(조회·저장) 1h, LLM 엔드포인트+프롬프트 1.5h, 테이블+샘플 데이터 1h, 위험 등급 +2~4h.
- 1인 가용 시간: 1일차 14:30~20:00 + 2일차 08:00~11:00 ≈ 8.5h. **계획은 그 60%(약 5h) 이내**. 넘는 사람이 있으면 "있으면 좋음" 기능부터 버리자고 제안한다.
- 모든 필수 기능이 사용자 흐름 단계와 데모 시나리오에 연결되는지 본다. 연결되지 않는 기능은 버림 후보로 표시한다.
- "화면 구성" 칸에는 화면 유형(대시보드 / 입력→결과 / 목록→상세)과 쓸 부품(`web/components/ui` 에 있는 것만)을 적는다 (`ui-design` 스킬이 이것을 따른다).

## 4. 계약 초안
- `docs/API_CONTRACT.md` 의 템플릿대로 기능마다 화면→web, web→ai 항목을 **상태: 초안** 으로 쓴다.
- 응답 형식은 `{ ok, data?, error? }`. 필드 이름은 영어 camelCase, 화면이 그대로 보여 줄 수 있는 모양으로 (목록은 배열, 숫자는 숫자 타입, 날짜는 ISO 문자열).
- AI 응답은 자유 문장 대신 필드가 정해진 JSON 으로 받는다 (화면에 구조화해서 보여 주기 위해).
- 확정은 담당자들과 확인한 뒤 정민이 상태를 "확정" 으로 바꾼다. 이 스킬은 "확정" 으로 쓰지 않는다.

## 5. 테이블 초안
- `web/db/schema.sql` 은 영진 담당이므로 직접 고치지 않는다. Oracle 문법 `CREATE TABLE` 초안을 보고서에 적고, PLAN B 의 DB 칸에 테이블 이름만 적는다.
