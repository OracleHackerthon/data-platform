# start: 기능 작업 시작

사용자는 git을 모른다고 가정한다. 명령은 네가 실행하고, 결과는 쉬운 말로 보고한다.

1. `git status` 로 저장되지 않은 변경이 있는지 본다. 있으면 멈추고 "저장하지 않은 작업이 있습니다. submit 으로 먼저 제출할까요?" 라고 묻는다.
2. `git switch main` 후 `git pull --ff-only`.
3. 사용자가 준 기능 이름을 영어 소문자와 하이픈으로 바꿔 `git switch -c feat/<이름>` (예: 요약 기능 → feat/summary). 같은 이름의 브랜치가 있으면 `git switch feat/<이름>` 후 `git merge main`.
4. `docs/PLAN.md` 에서 이 기능의 체크리스트를, `docs/API_CONTRACT.md` 에서 관련 계약과 상태를 읽는다. 없으면 멈추고 "PLAN.md에 이 기능이 없습니다. 정민에게 확인해 주세요." 라고 말한다.
5. 사용자가 누구인지 확인하고(AGENTS.md "사용자에 대해"), `docs/TEAM.md` 의 그 사람 절에서 수정할 수 있는 경로와 참고할 코드를 확인한다. 이 대화에서 이미 읽었으면 다시 읽지 않는다.
6. 보고 (3~5줄):
   - 브랜치 이름
   - 수정할 수 있는 폴더
   - 상대 쪽 상태 (화면 담당이면 API 가 MOCK 인지 실제인지, API 담당이면 화면이 기다리고 있는지)
   - 체크리스트 항목 목록과 첫 번째로 할 일
