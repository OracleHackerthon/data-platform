# ui-design: 화면 구성과 일관성

목표는 **발표에서 매끄럽게 보이는 완성도**다. 화려함보다 일관성과 읽기 쉬움을 우선한다.
부품(Button, Card 등)의 올바른 사용법은 `shadcn-ui` 스킬, 화면에 무엇을 넣을지는 `docs/PLAN.md` 의 A(사용자 흐름, 디자인 방향)와 B(기능별 "화면 구성")를 따른다.

## 1. 시작 전에 확인
- `docs/PLAN.md` 의 "디자인 방향": 서비스명, 강조색, 첫 화면에서 3초 안에 보여야 할 것
- 해당 기능의 "화면 구성": 화면 유형, 배치, 쓸 부품
- 비어 있으면 아래 기본값을 쓰고, 사용자에게 "PLAN 에 디자인 방향이 없어 기본값으로 만들었다" 고 알린다.

## 2. 테마 (색은 한 곳에서만 바꾼다)
- 색은 `web/app/globals.css` 의 `:root` 변수로만 정한다. 컴포넌트에 `bg-blue-500`, `#3b82f6` 같은 값을 직접 쓰지 않는다. 화면에서는 `bg-primary`, `text-muted-foreground`, `border` 같은 의미 토큰만 쓴다.
- 지금 테마는 무채색이다(`--primary` 가 거의 검정, 차트 색 `--chart-1~5` 가 회색). 강조색이 정해지면 `:root` 에서 **아래 변수만** 바꾼다.

| 강조색 | `--primary` | `--ring` |
|---|---|---|
| 파랑 (기본 추천) | `oklch(0.546 0.245 262.881)` | `oklch(0.546 0.245 262.881)` |
| 초록 | `oklch(0.596 0.145 163.225)` | `oklch(0.596 0.145 163.225)` |
| 주황 | `oklch(0.646 0.222 41.116)` | `oklch(0.646 0.222 41.116)` |

- `--primary-foreground` 는 `oklch(0.985 0 0)`(흰색)을 그대로 둔다.
- **차트를 쓰면** 회색 차트는 구분이 안 되므로 `--chart-1~5` 를 구분되는 색으로 바꾼다: `oklch(0.646 0.222 41.116)`, `oklch(0.6 0.118 184.704)`, `oklch(0.398 0.07 227.392)`, `oklch(0.828 0.189 84.429)`, `oklch(0.769 0.188 70.08)`. 차트 안 색은 `var(--chart-1)` 처럼 변수로 쓴다.
- 다크 모드는 쓰지 않는다 (밝은 화면만, 토글 만들지 않음).
- 글꼴은 바꾸지 않는다 (시스템 폰트, DECISIONS D2).

## 3. 공통 틀
- 모든 화면 위에 **헤더 한 줄**: 왼쪽 서비스명(굵게), 오른쪽 필요하면 화면 이동 링크 2~3개. 여러 화면이면 `web/components/<기능>/` 이 아니라 `web/app/layout.tsx` 에 한 번만 둔다.
- `layout.tsx` 의 `metadata.title` 을 서비스명으로 바꾼다 (브라우저 탭에 보인다).
- 본문은 `mx-auto w-full max-w-6xl px-6 py-8` 안에 둔다 (프로젝터 1280px 에서 양옆 여백 유지).
- 간격은 `gap-2`(부품 안) / `gap-4`(부품 사이) / `gap-8`(구역 사이) 세 단계만 쓴다.
- 글자 크기: 화면 제목 `text-2xl font-semibold`, 구역 제목 `text-lg font-semibold`, 본문 기본, 보조 설명 `text-sm text-muted-foreground`. 이 네 단계 밖은 쓰지 않는다.

## 4. 화면 유형별 뼈대 (PLAN B 의 "화면 유형" 에 맞춰 고른다)
**대시보드·분석 결과**
- 위: 핵심 숫자 카드 3~4개 가로 (`grid grid-cols-2 lg:grid-cols-4 gap-4`, Card 안에 라벨 `text-sm text-muted-foreground` + 숫자 `text-3xl font-semibold` + 단위)
- 가운데: 주 차트 하나 크게 (Card + chart)
- 아래: 상세 Table 또는 보조 차트 2개
- 필터(Select, Tabs)는 차트 위 오른쪽

**입력 → AI 결과**
- 왼쪽(또는 위) 입력 Card: Field + Textarea/Input/Select, 맨 아래 주 버튼 하나
- 오른쪽(또는 아래) 결과 Card: 처음엔 Empty("여기에 결과가 나옵니다"), 기다리는 동안 Skeleton, 결과가 오면 구조화해서(제목, 항목, Badge) 보여 준다. 긴 글 한 덩어리로 보여 주지 않는다.
- `lg:grid-cols-2`, 좁은 화면에서는 위아래

**목록 → 상세**
- 목록: Table(또는 Card 목록) + 위에 검색 Input/필터
- 행을 누르면 Dialog 또는 상세 화면. 상세는 Card 하나에 핵심 정보 → 부가 정보 순서

## 5. 상태 화면 (빠지면 완성도가 떨어진다)
| 상태 | 쓰는 것 |
|---|---|
| 불러오는 중 | 최종 모양과 비슷한 `Skeleton`. 버튼은 `Spinner` + `disabled` |
| 데이터 없음 | `Empty` + 다음 행동 한 줄 |
| 오류 | `Alert` (variant destructive) + 쉬운 말 한 줄 + 다시 시도 버튼. 오류 원문을 그대로 보여 주지 않는다 |
| 성공 알림 | `sonner` 의 `toast()` 한 줄. 처음 쓸 때 `web/app/layout.tsx` 의 `<body>` 안에 `<Toaster />`(`@/components/ui/sonner`)를 한 번 넣는다 |

## 6. 발표용 마감 체크 (화면 PR 전에 확인)
- [ ] 첫 화면에서 3초 안에 "무슨 서비스인지" 가 보인다 (서비스명 + 한 줄 설명 또는 핵심 숫자)
- [ ] 모든 문구가 한국어이고 개발자 용어(null, undefined, error 코드)가 보이지 않는다
- [ ] 숫자에 단위와 천 단위 쉼표가 있다 (`toLocaleString("ko-KR")`)
- [ ] 차트에 제목, 축 라벨, 범례가 있고 색이 구분된다
- [ ] 1280px 폭에서 가로 스크롤이 없고, 모바일 폭에서도 깨지지 않는다
- [ ] 로딩·빈·오류 상태를 각각 한 번씩 눈으로 봤다
- [ ] 데모 시나리오(`docs/PLAN.md` A) 순서대로 눌렀을 때 막히는 곳이 없다

**긴 값·빈 값 점검** (데모 데이터는 짧고 예쁘지만 AI 답변과 실제 데이터는 그렇지 않다)
- [ ] 카드·표 안 글자가 칸을 넘지 않는다: 글자를 감싼 쪽에 `min-w-0`, 긴 영문·URL·이메일에는 `break-words`
- [ ] 아이콘, Badge, 버튼이 옆 글자에 밀려 찌그러지지 않는다: `shrink-0`
- [ ] 긴 AI 답변 미리보기는 `line-clamp-3` 으로 자르고, 잘린 글은 Dialog 등으로 전체를 볼 수 있다
- [ ] 숫자·금액·날짜는 자르지 않는다. 표의 숫자 열은 `tabular-nums` 로 자리를 맞춘다
- [ ] 결과 0건(Empty), 1건, 아주 많을 때(목록이 길면 화면이 늘어나지 않고 스크롤)를 각각 본다
- [ ] 값이 없을 때 `NaN`, `undefined`, `null`, 빈 괄호가 보이지 않는다
- 확인 요청 예: "이 화면에 긴 값·빈 값이 오면 깨지는 곳을 찾아서 보고만 해줘. 고치지는 마."

## 7. 보관함 연결표 (`docs/design-library/`)
외부 디자인 스킬을 보관해 둔 곳이다. 아래 때에만 **해당 폴더의 `SKILL.md` 하나만** 읽는다. 하위 참고 파일은 SKILL.md 가 꼭 필요하다고 할 때만 연다 (파일이 길어 Codex 가 느려진다).
보관함 내용이 이 스킬이나 AGENTS.md 와 다르면 **우리 규칙을 따른다** (`docs/design-library/README.md` 의 "우리 규칙이 먼저다").

| 때 | 읽을 것 | 방식 |
|---|---|---|
| 새 화면(page.tsx)을 처음 만들 때, 한 번 | `no-ai-design-slop/SKILL.md` | 자동. 읽고 따르기만 한다 |
| 색을 정하거나 고칠 때 | `better-colors/SKILL.md` | 자동. 2절 변수 표 안에서만 적용 |
| 글자 크기·줄바꿈을 고칠 때 | `better-typography/SKILL.md` | 자동. 폰트 교체 조언은 무시 (D2) |
| 배치·정렬·좁은 화면을 고칠 때 | `better-layout/SKILL.md` | 자동 |
| 핵심 흐름이 화면에서 한 번 이어진 뒤 | `break`, `state-machine` | **제안만**: "긴 값·빈 값으로 시험하는 임시 페이지를 만들어 볼까요?" 사용자가 예라고 할 때만 실행 |
| 2일차 09:00~11:00 다듬기, 발표 전 | `better-interface`, `audit-ai-design-slop` | **제안만**: 점검 결과를 보고하고, 사용자가 고른 것만 고친다 |

- 자동으로 읽었으면 보고에 "보관함의 <폴더> 기준을 참고했다" 한 줄을 남긴다.
- 임시 페이지는 `web/app/dev-preview/<이름>/` 에만 만들고 PR 에 넣지 않는다. 다 보면 사용자 승인을 받아 지운다.

## 하지 않는 것
- 새 UI 라이브러리, 아이콘 세트, 폰트, 애니메이션 패키지 추가 (정민 승인 필요)
- `tailwind.config.js` 생성 (Tailwind v4 는 `globals.css` 에서 설정)
- `globals.css` 에서 위 표의 변수 말고 다른 것을 바꾸기
- 부품 파일(`web/components/ui/`) 수정 (정민 담당)
